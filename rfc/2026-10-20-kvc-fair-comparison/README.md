## 2. 工程边界

风险为中等：实验会占用独占节点资源，但不修改 DataSystem 生产代码、不执行故障注入。高风险面为接口完成语义、SHM 首次触页的 cgroup 归属、NUMA、客户端本地缓存、构建依赖和进程清理。三产品分别核对源码；公共驱动负责统一计时、样本汇总与资源采样。

热路径只增加统一客户端计时与直方图采样；不在每次请求中写磁盘或采集系统信息。数据构造、初始化、预置、PUT计时后读回与暖机在正式窗口之外；GET内容抽验及返回值检查位于测量循环内，单次SDK延迟排除这些检查，窗口QPS包含其开销。每个进程独占一个 SDK 实例，跨进程不共享 SDK 对象；进程由独立解释器启动，避免继承线程运行时。

状态为内存缓存，关闭持久化、溢写与多副本；本轮不推断故障恢复、断电一致性或跨节点 RDMA 性能。停止与重启只针对本任务记录的 PID/启动时间或实验 cgroup，不清理其他任务。实验配置均可撤销；保留环境前后快照和恢复指令。

## 3. 公平性原则

固定相同解释器版本、物理核集合、NUMA 节点、服务端与客户端资源上限、数据集、负载形状与重复次数。顺序运行三个产品，构建全部结束后才开始正式测量。同步 PUT 需数据提交完成；GET 需返回完整 bytes；EXIST 必须实际查询服务，不能用驱动本地集合替代。

优先共同支持的单节点双服务进程、CPU 内存缓存场景。当前主交付固定各产品原生支持的 TCP 数据路径；先前SHM/TCP路径实验单独归档。两套 profile 的适配、内存池与协议成本不同，分别统计并明确说明。若某产品缺少可比接口或发布版 CPU 支持，保留失败证据并分层展示，不伪造适配。
