本页的结论以 CodeGraph 命中的当前源码为准：Client Put 的 UB write 在 client 发起；Worker remote get 的 UB write 在数据 provider 端发起；Rebalance/Migrate 是 worker-worker RPC 后的数据迁移；TCP 故障隔离/恢复已有 etcd keepalive、HashRing、ClusterManager 的局部自愈链路。

1.2 最小结论

准入条件

所有写入和迁移目标都通过同一个组合判断：WorkerServiceMode(worker) == RUNNING 且 WorkerUbPathHealth(worker) == AVAILABLE。任一不满足，默认 fail fast。

最小修改原则

不新建复杂的数据面健康中心；新增轻量的 UB 路径观测缓存和准入接口，挂到现有 client put、worker provider write、remote get、migration/rebalance 入口。

隔离含义

这里的隔离不是把节点从集群摘除，而是对“向某 Worker 发生 UB 写入/迁移”的数据面准入关闸。读请求命中故障数据所在 Worker 时快速返回可识别错误。

TCP 边界

TCP/etcd 继续负责服务级网络断链、节点自愈、元数据/slot/ownership 恢复；UB 隔离只处理数据面路径，不能把局部 UB 观测直接提升成全局 DOWN。

2. 关键概念

2.1 全局事实与局部观测

Global Fact

由 master/etcd/hash ring/cluster metadata 维护的全局事实，例如 Worker 是否在 ring 中、slot 归属、primary copy、迁移任务状态。

Local Observation

由单个 client 或 worker 发起 URMA 单边操作时获得的局部观测。ERROR 4 是 UB 端口不可用的确定信号；CQE error、wait timeout、Jetty async event 需要按类型分类。

Admission Result

请求入口对两类信息做组合判断，但局部观测不能直接改写全局事实；最多阻止本进程继续写入，并通过 RPC/错误码把对端 UB 故障传出去。

2.2 Meta/Layout 与 Data Local

Meta/Layout对象位置、primary、slot、迁移任务。
Data Local某 Worker 本地内存/共享内存/SSD 中真实数据。
Worker Provider持有 object data 并被要求把数据写到 requester 的 worker。
Requester发起读写/迁移请求的一端，可能是 client 或 worker。
TransportURMA/UCP/TCP 的实际数据传输路径。

设计要避免把 transport 层“某一跳不通”误解释为对象不存在或元数据错误。新增错误语义建议为 K_OC_DATA_PROVIDER_UB_UNAVAILABLE 或同类 URMA data-plane code，表达“数据在该 Worker，但该 Worker 的 UB 路径暂不可用”。

3.2 职责拆分

发起端：Requester / URMA Writer

发起 URMA 单边操作的一端拥有最可靠的失败观测。它负责形成 UbOpOutcome、调用 UbFailureClassifier 分类，并通过 WorkerUbPathHealth 更新本地 health。

Worker Provider

只有 Worker 提供 object data，并常常根据 RPC 里的 URMA info 写回对端。URMA Write 的真实 completion/error 只在 Worker Provider 侧出现；Provider 失败后要把“对端 UB 不可写”的显式 URMA 状态反馈给 requester，避免 requester 只能靠 RPC 超时猜测。

服务级状态

WorkerServiceMode 只表达服务是否能参加集群读写、迁移和元数据恢复，复用 TCP/etcd 自愈链路，不和 UB 路径状态混在一起。

数据面准入

TransportPathAdmission 是最小公共入口，client put、worker remote get、migration/rebalance 都只问它“这个源/目标现在能否走 UB 写”。

命名建议：不要用过重的 DataPlaneHealthManager 语义。更贴切的是 WorkerUbPathHealth + TransportPathAdmission：前者记录局部观测和恢复状态，后者做组合准入。

6. 落地策略

6.1 最小修改点

新增轻量模块

WorkerUbPathHealth：进程内 peer -> health 状态，保存原因、时间、epoch、cooldown、probe 状态。

新增准入接口

TransportPathAdmission：给 put/get/migrate/rebalance 调用，组合服务态、UB 观测、fallback 策略。

新增错误码

新增或复用 URMA error 家族，表达“数据所在 Worker UB 不可用”与“目标 Worker UB 接收不可用”。

新增恢复 probe

先 cool-down，再 small probe。probe 成功只恢复该 peer 的 UB path，不改全局 membership。

6.2 修改路径

  • Client在 SendBufferViaUb* 前检查目标；失败后标记目标 UB path unavailable，并返回显式错误。
  • Provider Worker在 WriteViaFastTransport 失败后标记 requester UB path，并把显式 URMA operator status 放进 response。
  • Requester Worker在 PullObjectDataFromRemoteWorker 收到显式 UB unavailable 时快速失败或换副本；若只是 RPC timeout/failure，则按 provider/RPC suspect 处理，不当成对象缺失或本端 ERROR 4。
  • Migration在 ConnectAndCreateRemoteApi 或更上层目标选择前检查 migration target。
  • Fallback默认关闭；开启时仅允许小于等于 1MB 且非迁移路径的读取/写回，且要打点记录。

UB 恢复probe 成功后重新开放写入/迁移；TCP membership 不被 UB 单独修改。状态 UNAVAILABLE -> PROBING -> AVAILABLE，后续写成功。
TCP 闪断恢复走原有 keepalive/hash ring/cluster recovery；服务态恢复后再看 UB path。ClusterManager recovery 日志与 UB admission 状态均满足。

8. 待确认点

  • 错误码命名：建议放在 OC/URMA 交界处，保留 provider UB unavailable 与 requester UB unavailable 两类语义。
  • 恢复 probe 的实现：优先复用现有 handshake / small URMA write，不引入持续心跳。
  • fallback 策略：默认关闭；开启时建议只覆盖 <= 1MB 普通读写，不覆盖迁移和 bulk rebalance。
  • 局部观测是否需要广播：第一阶段不做全局传播，只通过 RPC response 传给本次 requester；后续如需要再加 coordinator 汇聚。
一句话版本：TCP 负责“这个 Worker 是否还能作为集群成员服务”，UB admission 负责“现在能不能往这个 Worker 的数据面写”。二者独立建模，在入口处组合判断。
