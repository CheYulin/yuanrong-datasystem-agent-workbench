# RFC：PR2165之后的写入专项报告与精简交付

状态：本地实现及回归通过，独立PR已创建，待评审；独立于已合入的PR2165。

RFC议题：https://gitcode.com/openeuler/yuanrong-datasystem/issues/1176

实现PR：https://gitcode.com/openeuler/yuanrong-datasystem/pull/2308

## 基线与范围

PR2165已合入主干，合入点为`db5524f75`，原PR HEAD为`bc73d43ea`。
这次从合入点创建新分支，只收敛后续报告中的增量，不重复提交基础解析、
QueryAndGet/Get归因、NUMA分析器，也不修改运行时数据路径。

## 问题

1. 原有写入章节缺少独立诊断页面、逐Trace证据、时间/Worker维度和完整导航。
2. 某些失败Create/Publish已有客户端RPC完成耗时，但latencySummary没有记录，
   导致可定位的父窗口全部留在残差。
3. 各页面布局和日志配色不同，后处理曾通过修改生成HTML实现，难以复用。
4. 示例分享包接近487MB，混入site草稿、中间模型和重复原包。

## 设计

### 写入后处理

增加`ds_trace_write_report.py`，输入现有`bottleneck.analysis.json`，输出独立写入HTML
和`write.refined.analysis.json`，不覆盖原模型。

- 只使用triage已经归入Trace的证据，不重新解包解析日志。
- Create/Publish父窗口要求标准日志前缀匹配Trace ID、时间戳与观察节点/线程。
- 完全相同的观测去重；多个调用不推断串并行；父窗口超过剩余残差不裁剪拼接。
- 只从足够的残差搬移；父窗口仍然是内部未细分，不等于网络、框架或CPU。
- Client最终状态与重试/错误标签分开。原始输入下载与保留证据下载明确区分。
- 同Client节点分5个时间段；Worker分析要求有Worker日志，失败RPC目标不算处理节点。
- 页面复用已验证的独立写入布局：编号导航、阶段图、分页排序、日志分组与异常耗时高亮。

### 页面与入口

将模板放入`trace_report_assets`，不把任何具体Run/Trace/IP或实验结论固化到代码。
suite增加可选`write_bottleneck_report`，保留原有调用兼容性。
统一分享页面字体、表格、代码/日志配色；专有图表和诊断逻辑仍由各分析器维护。
不在本次改动中强行合并读取、写入、NUMA的不同数据模型。

### 精简分享

增加`ds_trace_share_package.py`：从显式入口及suite manifest收集本地页面依赖。

- 静态href/src及嵌入的download_path参与依赖收集；其他动态页面必须显式列入入口。
- 原始下载文件按SHA256内容寻址，只存一份，更新页面下载路径，原始字节不变。
- ECharts提取为共享本地资源，不需要外部CDN。
- 未被引用的site草稿和中间模型不进分享包；原分析目录保留作完整复现。
- 已链接的JSON下载保留，不靠删除证据缩小体积。
- 拒绝路径越界、丢失依赖、重叠目录、覆盖现有输出。ZIP生成后做CRC检查。
- 输出包清单记录来源到实际路径的映射及体积，不将去重误认为跨Run合并。

## 非目标与兼容

不修改base triage解析器、元数据亲和/QueryAndGet逻辑或运行时库。
新写入页面和分享导出为显式调用，原CLI继续可用。
完整跨模型Trace证据共享、自动推断所有JavaScript动态依赖不在本轮范围。
代码渲染共用视觉规范，但不为统一格式改变各分析器的错误/耗时语义。

## 验证与风险

- 父窗口唯一性、重复记录、多观察者、多调用、超预算、错误Trace、已有父窗口、最终成功状态。
- 空写入数据、HTML转义、相对链接限制。
- 下载内容去重、路径遍历、缺失依赖、原树不变、ECharts顺序与离线资源。
- 基础triage/bottleneck/suite/NUMA/skill回归。
- 浏览器验证独立写入页、编号导航、过滤/分页、日志渲染及分享后的下载。

风险在报告证据归因和依赖收集，不涉及热路径、并发共享状态、持久化或恢复协议。
回滚可停止调用两个新脚本，继续使用原分析目录；原始数据与旧模型不被覆盖。

## 交付

DataSystem使用独立fork分支提交PR；RFC正文在workbench保存并同步到RFC议题。
PR和RFC相互关联，验证结果与后续范围在评审中明确，不将初步窗口定位写成闭环根因。

## 已执行验证

七组Python测试共184项通过，覆盖基础triage、bottleneck、suite、NUMA、skill以及新增写入与打包测试。
独立写入候选页在2,959条写入样本上通过桌面/窄屏导航、分页、筛选与日志渲染检查。
分享导出的样本页通过离线浏览器复查；原始文件去重、越界拒绝和资源引用由自动测试覆盖。
新增/修改行敏感信息检查为0项；未提交任何真实日志或生成报告。
未在本次RFC中承诺全量报告的固定缩小比例，实际结果由package.manifest.json记录。
