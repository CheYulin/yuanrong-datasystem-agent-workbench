Client Direct Read Target Development View

目标态开发视图，面向 PR #1119 整体模块设计：最大化复用 client/worker 的 meta/data read flow， 但把 feature gate、fallback、cutback、hash ring 生命周期等 client 策略留在 client 层。 代码行预估口径为“整个 PR 目标态相对 base 的总变动”。本地分支相对 origin/master 混有大量非 PR 历史文件， 因此这里以 GitCode PR bundle 的 64 个文件作为 PR 范围基线。

共用控制面 ReadMetaFlow

负责 route、QueryMeta 分组、moving/redirect、payload merge。

共用数据面骨架 ReadDataFlow

负责 not found、inline/remote payload、payload_info、part_index、顺序对齐。

角色差异 DataTransport

client remote TCP 与 worker local/gateway data path 分别实现。

负责人视角的规模判断

判断项 结论 原因
合理文件数 70 ~ 85 files Direct read 需要 client/common/worker/proto/build/test 同时落地。若超过 90 文件，要检查是否混入 unrelated cleanup。
合理净增行数 约 +5k ~ +7k 包含完整 ST/UT 时这个量级可接受；但 production code 应集中在 common flow、client policy、worker transport 三处。
当前最大结构风险 复用重心偏 Meta，Data 仍偏 client-only 如果要求“尽可能复用”，worker data path 必须成为 shared ReadDataFlow 的真实调用方。
不应接受的增长 client direct_read 继续单边膨胀 新增 data 能力应优先进入 common flow 和 transport interface，而不是继续扩大 DirectReadFlow。

开发检查点

检查点 通过标准 风险信号
真实复用 Client 和 worker 都实际调用 ReadMetaFlow 与 ReadDataFlow。 出现 NullDataClient、空 transport、只为编译通过的 adapter。
生命周期 DirectReadSession 用 mutex + shared_ptr 管理 ring source/RPC adapter。 请求 flow 持有可被另一个线程重置的 raw pointer。
Ring version Worker snapshot 带 authoritative revision，client 不接受旧 revision 覆盖新 snapshot。 version = -1 混用 etcd 和 worker snapshot。
Timeout Data TCP 显式使用 timeout 0 或 request deadline，并有 slow/hang data worker 测试。 (void)subTimeoutMs 且没有收敛测试。
Batch data 按 data worker 分组，复用 transport；最好跨 worker 并发。 MGet 中每个 object 串行创建 channel/stub。
Scale coverage 断言 ring refresh/revision/moving/redirect，而不只是最终读成功。 Fallback 成功掩盖 direct route 错误。
