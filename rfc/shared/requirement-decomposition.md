# 需求分解: IR → SR → AR

## RFC1: 滚动升级原地恢复

### IR-1: Worker 本地持久化支持

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-1.1 | Checkpoint 创建 | 10s 周期成功生成 Checkpoint，大小 < 1GB | `ls -la checkpoint_data/` 检查文件 |
| SR-1.2 | Checkpoint 完整性校验 | CRC32 校验通过，损坏时自动回退到上一 Checkpoint | 手工损坏 → 自动回退 |
| SR-1.3 | Checkpoint 空间管理 | 保留最近 3 个，自动清理旧 Checkpoint，磁盘不超限 | 测 4 个周期 → 最老被删 |
| SR-1.4 | Checkpoint 性能影响 | 对正常 Put/Get 吞吐影响 < 5% | dsbench 对比测试 |
| SR-1.5 | RocksDB 兼容性 | 同大版本 (v0.8.x) 打开已有 DB 成功 | 多版本交叉测试 |

### IR-2: Worker 快速恢复

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-2.1 | 正常恢复 | 从 Checkpoint 恢复到 RUNNING < 3s | `time` 量恢复耗时 |
| SR-2.2 | 异常恢复 | 崩溃后从最近 Checkpoint + WAL 恢复，丢失 < 10s 数据 | kill -9 测试 |
| SR-2.3 | 无 Checkpoint 启动 | 全新集群启动，等 peer 对账 | 首次启动日志 |
| SR-2.4 | 恢复后服务可用 | 恢复后 5s 内正常服务 Put/Get | 恢复后立即压测 |

### IR-3: Hash Ring 升级态

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-3.1 | UPGRADING 状态机 | NO_INIT→INIT→RUNNING→UPGRADING→RUNNING 转换正确 | 状态机测试 |
| SR-3.2 | 升级中保留读 | UPGRADING 态下 Get 请求正常响应 | 升级中压测 GET |
| SR-3.3 | 升级中暂停写 | UPGRADING 态下 Put 请求返回 TRY_AGAIN | 升级中压测 PUT |
| SR-3.4 | 升级失败回滚 | 超时 30s 自动触发回滚，数据不丢失 | 注入升级失败 |

### IR-4: 版本兼容

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-4.1 | 同大版本互操作 | rc24 ↔ rc26 可正常通信 | 混合集群测试 |
| SR-4.2 | Checkpoint 版本检测 | 不兼容版本打开 Checkpoint → 降级到全量恢复 | 跨大版本测试 |

## RFC2+3: 数据多副本 (可靠性 + 性能)

### IR-5: 写入多副本

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-5.1 | 同步写入主副本 | Primary Put 完成，数据在 Primary 节点持久化 | 单副本验证 |
| SR-5.2 | 异步写入备副本 | PutEnd 后 1s 内备副本标记 COMPLETE | 检查 seqno |
| SR-5.3 | 两阶段写入协议 | PutStart→Write→PutEnd，PutEnd 前 Get 返回 NOT_FOUND | 竞态测试 |
| SR-5.4 | 副本数可配置 | replica_count=1→N，容量不足时 best-effort | N=1/2/3 测试 |
| SR-5.5 | 写入 P99 < 3ms | 8MB KV，N=2 写入，P99 < 3ms | dsbench |

### IR-6: 副本反亲和

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-6.1 | 跨节点分布 | 同一 Object 的 2 个副本不在同节点 | 检查分配结果 |
| SR-6.2 | 跨 Rack 分布 (N=3) | 3 副本分布在不同 Rack | 多 Rack 拓扑测试 |
| SR-6.3 | NUMA 亲和优先 | 同 NUMA node 节点优先选为 Primary | 单节点多 NUMA 测试 |
| SR-6.4 | 不跨 HCCS | Primary 读写不经过 HCCS | 拓扑检查 |

### IR-7: 主备故障切换

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-7.1 | 故障检测 | 3s 内检测到 Primary 故障 | kill -9 + 计时 |
| SR-7.2 | 备副本提升 | PromoteToPrimary 完成，P99.99 < 5ms | 1000 次故障切换测 P99.99 |
| SR-7.3 | Client 无感切换 | Client Get 自动路由到新 Primary | Client 日志检查 |
| SR-7.4 | 主副本恢复 | Primary 恢复后转为 Backup，增量对账 | 恢复测试 |

### IR-8: 数据恢复

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-8.1 | 备副本恢复 | Backup 故障后 5min 内从 Primary 恢复 | kill Backup + 观察 |
| SR-8.2 | 恢复不阻塞读写 | 恢复过程中 Get/Put 正常 | 恢复中压测 |

### IR-9: 一致性同步老化

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-9.1 | TTL 同步 | 主备副本同时到 TTL → 同时淘汰 | 设 TTL=10s → 观察 |
| SR-9.2 | 一致性对账 | 每 60s 对账一次，seqno 一致 | 长时间运行测试 |

### IR-10: 均衡读取 + NUMA 亲和写入

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-10.1 | 均衡读取 | 1写10读，各副本读次数偏差 < 20% | 统计读分布 |
| SR-10.2 | NUMA 亲和写入 | Primary 与 Client 同 NUMA node | 检查分配结果 |
| SR-10.3 | QPS +30% | 1写10读 8MB KV，多副本 vs 单副本 QPS 提升 > 30% | dsbench |
| SR-10.4 | P99.99 < 5ms | 同上场景，P99.99 < 5ms | dsbench |

## RFC4: 1K节点建链优化

### IR-11: ZMQ 连接池

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
| SR-11.1 | 连接复用 | 1024 节点，每 Worker 连接数 < 10K | 连接数统计 |
| SR-11.2 | 连接获取 < 1ms | Acquire() 热路径 < 1ms | 性能测试 |
| SR-11.3 | 健康检查 | 断连 30s 内检测并重建 | kill 对端 + 观察 |
| SR-11.4 | 连接数上限 | 超 pool_size → 排队，100ms timeout | 压测 |

| SR-12.2 | 负载均衡 | 各 Jetty 使用率偏差 < 15% | 监控指标 |
| SR-12.3 | Jetty Cache miss | [芯片厂商]环境 Cache miss rate < 1% | 性能分析 |

### IR-13: URMA QP 池化

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|

| SR-13.2 | QP 复用 | 相同 peer 复用 QP，< 1ms | 性能测试 |
| SR-13.3 | 扩缩容毛刺 | 100→200 节点，P99.99 < 10ms | dsbench |

### IR-14: 连接治理

| ID | 子需求 (SR) | 验收标准 (AR) | 验证方法 |
|----|-----------|-------------|---------|
