01 / BASELINE · COMPLETE BATCH CALLS

同机 KVC 性能对比
从批量接口到扩展边界

1 物理机 · 6 组实验

比较 DataSystem 与 Mooncake 的 PUT、GET 和 EXIST。先核对原生结果、重复轮次与资源窗口，再观察相同预算下的吞吐、延迟和 CPU 使用。

批量为每次调用的 keys 数：1 / 16 / 256 / 4096。基础组要求 3 轮均通过，柱高为中位数，细线为最小值至最大值；这不是置信区间。完整批量调用的 P99 为原生直方图桶上界。

02 / WORKER SCALING · FIXED TOTAL BUDGET

增加 workers，观察单位预算的收益

单逻辑节点，workers 为 1 / 2 / 4 / 8，B=1。服务端总 CPU 与内存预算固定，中心组件计入同一预算；增加进程不会增加总资源。单轮规格扫描用于观察趋势，不能证明统计显著性。

03 / CLIENT SCALING · CONCURRENCY

从 1 到 32 clients，识别吞吐平台

单逻辑节点，B=1，clients 为 1 / 2 / 4 / 8 / 16 / 32。客户端总 CPU 预算固定，实际平均使用核数与服务端负载同时记录；并发数不等于新增 CPU 核。

04 / CENTRAL QUOTA SENSITIVITY · EXIST

用配额敏感性验证中心路径

单逻辑节点，workers × 中心 CPU 配额 1 / 2 / 4 核，B=1，仅扫描 EXIST。吞吐平台、中心配额利用率和配额变化的影响需共同验证；不能仅凭曲线拐点宣称瓶颈。

DataSystem · Coordinator

Coordinator 负责集群协调；KV 元数据由 workers 承载。这里的中心 CPU 不是 worker 元数据处理 CPU。

Mooncake · 单 Master

增加 workers 是增加 store peers；本实验未将单 Master 的元数据按 workers 分片。

中心 CPU 配额来自子 cgroup 的 cpu.max，中心继承服务端 cpuset，并非独占物理核；限额计入服务端总预算。利用率略高于 100% 时保留观测值，不截断。

Mooncake 的冻结配置同时设置 RPC 线程数：1 核配额 / 4 线程、2 核 / 4 线程、4 核 / 8 线程。1→2 核保持线程数不变；2→4 核同时增加线程，曲线验证的是中心配置敏感性，不能归因为纯 CPU 单因素。

05 / LOGICAL NODES · SAME PHYSICAL HOST

固定 4 workers，改变逻辑节点划分

比较 1 / 2 / 4 个同机逻辑节点，总 workers 固定为 4，共享相同服务端总预算。N=1 取第 2 章 worker_scaling 的 W=4 实测点；N=2 / 4 分别读取独立运行。各组按 loopback / host ID 区分，没有跨物理机网络结论。
