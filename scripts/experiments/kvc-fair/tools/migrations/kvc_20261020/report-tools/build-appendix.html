DataSystem：源码校验与构建命令
git clone --depth 1 --branch v0.9.2.rc44 \
  https://gitcode.com/openeuler/yuanrong-datasystem.git datasystem
cd datasystem
test "$(git rev-parse HEAD)" = 2ff37e2f7c5fb45f3feea7c3fb969b8f84b920d6
export DS_OPENSOURCE_DIR=/path/to/private-thirdparty-cache
PYTHON_ROOT=/path/to/cpython-3.11.15-linux-x86_64-gnu
bash build.sh -b cmake -r -X off -M off -A off \
  -P "$PYTHON_ROOT" -t off -j 8
tar -xzf output/yr-datasystem-v0.9.2.tar.gz -C output
"$PYTHON_ROOT/bin/python3.11" -m venv .venv
.venv/bin/python -m pip install --force-reinstall --no-deps output/*.whl

首次构建在 Python 尚未就绪时使用 -P on，随后在主 configure 前通过 Python3_ROOT_DIR / Python3_EXECUTABLE 指向 3.11.15；重放配方直接传解释器目录。grpc 第三方预构建首次出现动态库搜索问题，主 configure 按依赖顺序自动重试成功，没有修改产品源码。完整重放配方

Mooncake：Release TCP / CPU wheel 构建命令
git clone --depth 1 --branch v0.3.13.post1 \
  https://github.com/kvcache-ai/Mooncake.git source
test "$(git -C source rev-parse HEAD)" = 719735896c86b56fabec6cf3e825fb2ea640597a
# 先准备 CPython 3.11.15 venv、Python 构建依赖；xxHash 0.8.3 源码安装至私有 prefix
export CMAKE_PREFIX_PATH=/path/to/mooncake/deps
export CC=/opt/rh/gcc-toolset-15/root/usr/bin/gcc
export CXX=/opt/rh/gcc-toolset-15/root/usr/bin/g++
export CMAKE_BUILD_PARALLEL_LEVEL=8
export CMAKE_ARGS='-DCMAKE_BUILD_TYPE=Release -DENABLE_DEBUG_SYMBOLS=OFF -DWITH_STORE_RUST=OFF -DUSE_CUDA=OFF -DUSE_TENT=OFF -DUSE_ETCD=OFF -DUSE_HTTP=ON -DSTORE_USE_ETCD=OFF -DBUILD_UNIT_TESTS=OFF -DBUILD_EXAMPLES=OFF -DBUILD_BENCHMARK=OFF'
venv/bin/python -m pip wheel ./source --no-deps --no-build-isolation \
  --wheel-dir wheels --verbose
venv/bin/python -m pip install --force-reinstall --no-deps wheels/*.whl

首次 USE_HTTP=OFF 编译因 MetadataStoragePlugin 不完整类型失败，恢复上游默认 USE_HTTP=ON 后成功；运行时仍关闭 HTTP metadata server，二者含义不同。xxHash 0.8.3 从固定归档构建，io_uring 可选依赖未启用。完整重放配方

A.3 关键运行配置：旧 TCP 与后续纯 KV 分开列示

产品 / 项目旧单 key TCP 页面实际配置R7 批量 pure-kv 实际配置
共同资源与拓扑同节点两个服务端点；服务端总额度 8 CPU / 12 GiB，客户端 8 CPU / 12 GiB，监控 2 CPU / 1 GiB；cgroup 独立 CPU / NUMA，swap=0；TCP，单次只压一个产品。两实例的控制面和路由语义不同，不宣称完全同构。
DataSystem 内存与线程shared_memory_size_mb=4096/worker；oc_thread_num=8、brpc_server_num_threads=8、brpc_max_concurrency=128。这里 4 GiB 是 Worker 数据池容量，不代表通过 SHM 传输。
DataSystem 传输与缓存ipc_through_shared_memory=false；enable_rdma=false、enable_urma=false；l2_cache_type=none、spill_directory=''、spill_size_limit=0；SDK enable_local_cache=False，使用路由式 KV SDK。
DataSystem RocksDB / stream未显式关闭 RocksDB / stream；两个 Worker 未显式隔离默认 RocksDB 目录，因此旧 DataSystem 性能不能作为隔离公平基线。rocksdb_write_mode=none；sc_regular_socket_num=0、sc_stream_socket_num=0；每 Worker 独立 fresh rocksdb_store_dir。无 DB/MANIFEST/SST/WAL 制品；仍有普通 eviction 状态文件，不声称零 IO 或零 Rocks 库初始化。
DataSystem 观测开关log_monitor=false、minloglevel=2；未使用后续 pure-kv 的全部关闭项。再关闭 json_log_monitor、enable_perf_trace_log；request_sample_rate=0、access_sample_rate=0；SDK monitor/perf trace 关闭、ERROR 保留。未找到 SDK JSON monitor 的官方环境开关，不宣称已关闭。
Mooncake 数据与元数据classic tcp / P2PHANDSHAKE；每 peer 4 GiB segment，128 MiB local buffer；client store capacity=0；MC_STORE_LOCAL_HOT_CACHE_SIZE=0、MC_STORE_MEMCPY=0；master rpc_thread_num=4。关闭 HA、offload、HTTP metadata server、oplog，dynamic replication=off。
Mooncake TCP 容量未覆盖队列参数；锁定源码默认 queue=1024、pending=1024、lanes=4、admission=1000ms。MC_TCP_MAX_QUEUED_TRANSFERS_PER_PEER=8192、MC_TCP_MAX_PENDING_ADMISSIONS_PER_PEER=8192；MC_TCP_LANES_PER_PEER=4、MC_TCP_ADMISSION_TIMEOUT_MS=1000；所有 B 使用同一组值。
Mooncake 后台特性未使用后续 pure-kv 关闭集，不把 ERROR 日志级别当作 metrics 等已关闭。store/TE metrics 关闭；enable_metric_reporting=false、snapshot/restore、disk eviction、KV events、多租户、offload_on_evict/force_evict、promotion_on_hit 均 false；eviction_ratio=0、eviction_high_watermark_ratio=1；checksum=false。admin listener / 必需后台循环保留。
LMCache CPU / TCPCPU MP engine_driven + pickle/TCP；--l1-size-gb 4/server、--chunk-size 1、--shm-name ''、--no-l1-use-lazy、--worker-reap-timeout-seconds 0；不配置磁盘 L2。8 GiB 预触页计入资源。
LMCache 后台特性--eviction-policy LRU；LMCACHE_LOG_LEVEL=ERROR、LMCACHE_TRACK_USAGE=false；observability / metrics / logging subscribers 沿用默认。--eviction-policy noop --disable-observability --disable-metrics --disable-logging --kv-event-log-size 0 --coordinator-url ''；LMCACHE_COORDINATOR_EVENT_REPORTING=false。HTTP health frontend 与 1Hz 控制线程保留；本地 P2P EXIST 协议保留。

R7 配置按纯内存 KV 需求精简，没有穷举全部参数，不能称为全局最优；这些开关未单独做收益归因实验。关闭持久化的配置不用于证明重启恢复能力。本次附录不重新构建或压测，原始数据、ZIP、失败和既有验收收据保持原字节；既有收据描述补充前版本。
