1. 先确定比较边界

本报告比较发布源码的本机 CPU 部署：DataSystem 使用本机 RPC 控制与 SHM 候选路由，Mooncake 使用 TCP，LMCache 使用 MP SHM + RPC。三条路径的端到端结果包含各自协议和适配成本；不由此推断跨机 RDMA、GPU KV 或推理 TTFT。

DataSystem

两个 KVC Worker + ETCD；总数据池 8 GiB。关闭客户端本地缓存，原生 metadata/provider 路由。

Mooncake

Master + 两个 4 GiB peer；负载客户端存储容量为 0，单副本，关闭本地热缓存。

LMCache

两个独立 MP CPU Server，各 4 GiB；uint8 单 chunk 映射 bytes，prepare / commit 确认。双实例不等价于统一分布式元数据集群。

PUT 是固定量的新 key 插入（1 KiB 共 64 MiB，另外两个尺寸共 2 GiB），短于 10 秒时明确标记。GET / EXIST 暖机 3 秒、测量 20 秒；预置、校验和清理均与接口计时分阶段。同一用例内 PUT→GET→EXIST 顺序固定：GET 的 64 MiB 热集之外保留先前 PUT 背景数据，EXIST 复用该热集；下一用例重启空服务。P99 来自全客户端合并直方图，桶宽约 1.56%。

4. CPU、内存与磁盘代价

内存均按 server + client 相加。实线展示 memory.stat 的 anon + shmem，虚线保留 memory.current 总计费；普通文件缓存可能跨用例保留，因此不把总计费直接当成当前产品独占内存。匿名+SHM 包含独立 SDK 的匿名堆与共享池，避免共享页在 RSS 中重复统计；首次触页可能计入客户端。这与嵌入已有推理进程的增量内存不同。数据池为内存，元数据、日志与控制组件仍可能产生磁盘 I/O。原始监控包含 iostat、dstat、pidstat、mpstat、perf；内核未提供 PSI，标记不可用。资源是 1 秒采样，短 PUT 窗口可能没有足够样本。计费字段与所有权依据Linux cgroup v2 文档。

5. 公平性检查与可推广范围

相同的约束

Python 3.11.15；服务端与客户端各 8 个独立物理核、同 NUMA；服务端与客户端各 12 GiB 上限，禁用 swap；确定性 bytes 与相同 key；串行产品、随机顺序、三次重复。

原生接口成本

LMCache 查询含 lookup / wait 与锁释放，GET 包含读事务；DataSystem 和 Mooncake 使用各自原生单接口。比较的是明确语义下的调用体验，不能解释为单次底层 RPC 的优劣。

实验外的能力

不覆盖容量溢出、持久化、故障恢复、跨机网络、GPU 与推理。CPU/协议/分配器默认路径不同；LMCache 1 KiB chunk 按至少 4 KiB 对齐，内存开销随之变化。
