1. 批量含义与可比边界

主图配置：{{PROFILE_NAME}}。默认配置失败单独保留，不与旧单 key 或当前主矩阵合并。
B 是一次 API 的独立 key 数。B=4096 对应 4 MiB 对象数据。首次 PUT 使用新 key，固定 262144 keys / 256 MiB；UPSERT 单独观察真正更新。先运行独立 READ epoch：GET / UPSERT / EXIST 只保留 65536 keys / 64 MiB 热池、20 秒窗口，预热 3 秒。随后每个支持 B 的首次 PUT 都启新服务并预置同一热池；PUT 预热固定另建并读回 32768 keys，测前常驻 98304 keys / 96 MiB；测量再写 262144 新 keys，不累积到下一 B 或 READ。

同一资源边界

服务端合计 8 CPU / 12 GiB，客户端合计 8 CPU / 12 GiB；独立 CPU、NUMA 与无 swap cgroup。每次只运行一个产品。

保留原生接口边界

DataSystem 4096-key GET 在 SDK 内分块；Mooncake batch 返回后完成传输与主节点确认。适配器不做逐 key 数据 API 回退。

N/A 与协议成本

LMCache PUT / GET 只有 B=1；UPSERT 全部 N/A。EXIST 使用 P2P L1 索引批量 lookup、轮询与解锁，成本包含该协议。

2. 部署隔离与容量配置

默认 Mooncake 曾在 B=4096 的带跟踪门禁与无跟踪 C8 smoke 中出现 TRANSFER_FAIL；队列溢出仅为未确认的源码候选解释。r3 正式尝试的 DataSystem 两 Worker 共用了默认 RocksDB 目录，伴随 SST 缺失/大小错误和 RPC 超时，属于实验部署隔离遗漏，不能作为产品 API 缺陷结论。所有原始失败单独保留，主矩阵使用新的独立目录与门禁。
